# 팀 작업 방식

- 문서, 스펙, 설명은 한국어로 작성한다.
- 스펙 태스크는 한 번에 하나씩 실행하고, 끝나면 변경 파일, 실행한 테스트, 남은 문제를 요약한다.
- 한 태스크의 변경은 PR 하나(약 400줄 이하)에 담길 크기로 유지한다. 너무 크면 태스크를 나누자고 제안한다.
- 요구사항에 없는 기능을 임의로 추가하지 않는다. 필요해 보이면 제안만 한다.
- 새 파일을 만들 때 목적을 파일 상단 주석 한 줄로 적는다.
- 팀원이 코드를 설명할 수 있어야 하므로, 복잡한 로직에는 왜 그렇게 했는지 주석을 단다.
