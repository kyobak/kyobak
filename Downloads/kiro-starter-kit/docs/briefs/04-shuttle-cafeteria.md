# 브리프 04: shuttle-cafeteria (셔틀 대기줄과 학식 혼잡도)

## 목적
셔틀 정류장과 학생식당·푸드코트의 줄 상태, 예상 대기시간, 시간표·메뉴를 보여준다. 영상 수치(02 스펙)를 우선 쓰고 없으면 제보·예측으로 대체한다.

## 사용자 스토리
- 학생으로서, 정류장을 고르면 다음 출발 시각과 몇 번째 버스에 탈 수 있는지 알고 싶다.
- 학생으로서, 식당별 오늘 메뉴와 지금 줄에 서면 몇 분 걸리는지 알고 싶다.
- 학생으로서, 영상이 없는 곳은 줄 길이를 짧음·보통·김 중에서 제보하고 싶다.

## 요구사항 초안 (EARS)
- REQ-SHT-01: 시스템은 정류장별 셔틀 시간표를 저장하고 현재 시각 기준 다음 출발 3회를 표시해야 한다.
- REQ-SHT-02: WHEN 사용자가 정류장을 선택하면, 시스템은 GPS를 쓰지 않고 선택한 정류장 정보만 사용해야 한다.
- REQ-SHT-03: WHEN 사용자가 정류장을 선택하면, 시스템은 줄 인원과 버스 정원으로 계산한 탑승 가능 회차를 표시해야 한다.
- REQ-SHT-04: IF 시간표 데이터가 7일 이상 갱신되지 않았으면, THEN 시스템은 "시간표 확인 필요" 경고를 표시해야 한다.
- REQ-CAF-01: 시스템은 식당별 오늘 메뉴를 하루 한 번 이상 수집해 표시해야 한다.
- REQ-CAF-02: WHILE 최근 15분 안의 영상 수치와 제보가 모두 없는 동안, 시스템은 예측값을 표시하고 '예측'임을 함께 표기해야 한다.
- REQ-CAF-03: WHEN 메뉴 수집이 실패하면, 시스템은 마지막 성공 데이터를 수집 시각과 함께 표시해야 한다.
- REQ-CAF-04: 시스템은 식당 운영 시간 외에는 혼잡도 대신 "운영 종료"를 표시해야 한다.

## 데이터
`resources(kind=shuttle|cafeteria)`, `shuttle_timetables`, `menus`, `vision_metrics`, `reports`, `predictions`
크롤러는 `jobs/`에 두고 GitHub Actions로 주기 실행한다. 수집 전 대상 페이지의 robots.txt와 이용 조건을 확인한다.

## 범위 밖
셔틀 실시간 차량 위치, 사용자 위치 추적, 식당 결제·주문.

## 완료 기준
정류장·식당 상세 화면이 영상·제보·예측 세 가지 출처 모두에서 올바르게 표시된다. 탑승 회차 계산과 시간표 경고 테스트가 통과한다.
